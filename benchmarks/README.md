# M0 · Сценарий для сравнения MCP

Установите зависимости из requirements.txt и Chromium (`python -m playwright install chromium`). Из корня клона выполните `python -m benchmarks.m0`. Для установленного Chrome можно задать STUDIO_TEST_BROWSER=chrome. JSON выводится в stdout, журнал SDK — в stderr.

Генератор fixtures.py воспроизводит 100 разных URL и вторую редакцию одной публикации. Две отдельные позиции совпадают по компании и названию. Один срок истёк. Текущая дедупликация сохраняет 99 строк. Десять свежайших по дате публикации имеют HTML-формы с общим вопросом, обязательными email, PDF и письмом.

Сценарий использует настоящие stdio MCP, локальный HTTP, SQLite и Chromium. Вместо внешнего фида подаётся список записей, вместо модели — фиксированный ответ. Все запросы контекста браузера перехватываются. Подтверждение появляется после проверки значений HTML-формой. Профиль, PDF и база синтетические и удаляются после запуска. После первого вопроса MCP-клиент завершается, новый клиент читает состояние и отправляет подтверждённый ответ с запоминанием. Веб-сервер и вкладка остаются открытыми.

HTTP-метрика складывает длины JSON-тел запросов и ответов локального API; MCP-метрика складывает фактические UTF-8 JSON-RPC запросы и ответы tools/call, включая служебные поля. Обе исключают транспортные заголовки и разделители; handshake исключён. Медиана и p95 (nearest rank) измеряют полный вызов инструмента. Работа браузера асинхронна: чтобы нагрузка была повторяемой, стенд ждёт завершения этапа вне таймера вызова. workflow_seconds включает эти ожидания и переподключение. Фиксированный провайдер не сообщает usage. Байты не пересчитываются в токены. Сравнивайте на одной машине; временные метки немного меняют размер ответов.
