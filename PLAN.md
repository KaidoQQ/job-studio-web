# План развития Job Studio

Цель ближайшего цикла — сократить число ручных переходов и повторных чтений при сохранении точного учёта отправок. Рассчитываем стоимость отдельно для агента MCP и для AI-провайдера внутри сервиса.

## Стартовая точка и измерения

**✅ M0 · Выполнено.** [Стенд и исходные измерения в PR #1](https://github.com/KaidoQQ/job-studio-web/pull/1). Подготовить обезличенный набор из 100 вакансий, включая одинаковые названия у одного работодателя, две версии одной публикации, истёкшее объявление и 10 анкет с повторяющимися вопросами. Воспроизвести один сценарий с фиксированными ответами провайдера: собрать, выбрать 10, подготовить письма, заполнить тестовые формы, один раз прерваться и продолжить. Зафиксировать в PR число вызовов MCP и AI, байты JSON на границе HTTP и отдельно на границе MCP, медиану и p95 задержки, исход каждого отклика. Токены считать токенизатором выбранной модели или брать из usage провайдера. Если доступны только байты, подписывать метрику как байты. Тесты запускаются без личного профиля и отправок работодателям.

## Совместная работа

После M0 и B1 один участник может взять A1 и фикстуры браузера, второй — B2 и курсор событий. A2 и A3 затрагивают один модуль и требуют согласования, если идут параллельно. Для каждого пункта завести issue с его ID, назначить одного исполнителя и указать зависимые PR. Изменение контракта HTTP/MCP начинать с примера запроса, ответа и поведения старого клиента. Второй участник проверяет тесты и воспроизводимость результата. В PR производительности приложить значения до и после на одном наборе данных. После M0 выбрать численные цели по фактической нагрузке.

## Возможности следующего цикла

- Сводка изменений с прошлого запуска: новые подходящие позиции, просроченные и ожидающие ответа анкеты. Открывать полное описание только для выбранной вакансии.
- Учёт откликов по разным каналам: отдельная запись для отправленного письма, квитанции сайта и ответа работодателя. Позволит исключать уже обработанные компании при следующем поиске.
- Очередь ручной проверки с группировкой по вопросу. Пользователь видит, каким вакансиям подходит ответ, и выбирает, где его применить.
